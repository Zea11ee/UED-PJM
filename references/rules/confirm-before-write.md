# 确认后落库规则

**规则**：任何落表操作前，必须先出"父任务 + WBS 草稿"给需求方确认，收到明确同意后才能写入多维表格。

**触发条件**：
- 创建任务源（父任务）
- 创建 WBS 子任务
- 更新现有任务或 WBS

**确认前必须展示**：

父任务字段：
- 标题
- 源编号
- 归属项目（关联）
- 期望上线日期
- 优先级
- 状态
- 描述
- 附件
- 需求方
- UED 负责人

WBS 字段（表格形式）：
- 序号
- 任务名称
- 负责人
- 状态
- 预计工时
- 启动日期
- 结束日期

**来源**：2026-02-03 需求处理流程规范化。

**反例**：
- 若未经确认直接落库：
  - 可能写入错误的负责人
  - 可能排期与实际冲突
  - 需要额外的修改和回滚操作
  - 影响项目执行数据的准确性

**确认话术示例**：
- 用户说"确认"、"落库"、"执行"、"可以"、"好的"等明确同意词
- 不明确时应追问："请确认以上草稿是否正确，确认后我将写入多维表格"
