# 模板：问题修复类（Bug Fix / Incident）

## 适用信号
- 需求编号以 `HSBUG`、`QXBUG`、`BUG` 开头
- 线上环境出现功能异常、样式错乱、数据错误
- 需要紧急排查和修复
- 通常没有完整的 PRD，直接从问题描述开始

## 推荐任务链（最小集）
1. 开发排查与处理（2h~6h）
2. 测试跟测/复现验证（1h~3h）
3. 回归验证（可选，0.5h~1h）

## 工时参考
- 简单样式/配置问题：开发 1h~2h + 跟测 1h
- 中等逻辑问题：开发 2h~4h + 跟测 2h
- 复杂排查问题：开发 4h~8h + 跟测 2h~3h + 回归 1h

## 常见命名
- `{模块名} - 开发排查与处理`
- `{模块名} - 复现与跟测`
- `{模块名} - 回归验证`

## 排期关键点
- 优先级通常较高（P1/P2），需当日或次日启动
- 开发与测试可并行（测试先复现，开发同步排查）
- 不需要 PRD 环节，直接从问题描述进入开发
- 修复后必须有验证环节，不可只有开发任务

## 任务源字段特殊处理
- 任务源标题不含编号，编号放"源编号/备注"
- 需求方填写表单提交人，非 UED 人员

- 2026-01-30 HSBUG202601301609：开发排查&处理 3h + 测试跟测 2h
- 2026-03-04 QXBUG202603041450：开发处理 3h + 复现与跟测 2h
